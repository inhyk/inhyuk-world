# publish-game 요구사항 명세

작성일: 2026-08-16

## 배경

서인혁이 만든 게임들을 seonn.dev 한 곳에 포트폴리오처럼 계속 쌓아 올릴 수 있게 한다.
어른 도움 없이 인혁이 혼자 발행까지 끝낼 수 있어야 한다.

## 조사에서 드러난 사실

- seonn.dev는 이미 살아있는 Next.js 사이트다 (`inhyk/inhyuk-world` → Vercel)
- 게임은 이미 게임별 독립 GitHub 저장소 + 독립 Vercel 프로젝트로 배포되고 있었다
- Vercel에는 게임 프로젝트가 8개 있었지만 사이트에는 2개만 등록돼 있었다
- `~/inhyuk/`에는 게임 폴더가 30개 이상 있고, 대부분 git도 배포도 없다
- 허브의 `GameCard` / `ScreenshotGallery`는 `thumbnail`과 `screenshots` 필드를 받아만 두고 실제로는 렌더링하지 않았다. 이모지 하드코딩 맵이 있어서 새 게임은 무조건 🎮로 표시됐다
- `games.ts`에 적힌 Rhythm Game의 `playUrl`이 404였다 (죽은 주소)

## 확정된 결정

**호스팅**
: Vercel 유지. seonn.dev가 이미 Vercel Next.js로 서비스 중

**레포 구조**
: 게임별 독립 저장소 + 허브. 모노레포 이사는 하지 않음 (기존 8개 배포를 다 갈아엎어야 하고, Node 서버형 게임 처리가 복잡해짐)

**발행 방식**
: Claude Code 슬래시 커맨드 `/publish-game`. 게임 폴더에서 한 번 실행

**메타데이터**
: 게임 폴더의 `game.json`이 단일 진실 소스. 없으면 대화형으로 생성

**썸네일**
: 배포 후 Playwright(설치된 크롬 사용)로 자동 캡처. 게임 폴더에 `screenshots/`가 있으면 그걸 우선 사용

**실행 환경**
: 인혁이 맥에서 `inhyk` GitHub 계정 + 인혁이 Vercel 계정(`inhyuks-projects`)으로 단독 실행

**게임 저장소 공개 범위**
: public (기존 게임들과 동일)

**발행 도구를 어디에 둘 것인가** (2026-08-16 변경)
: 처음에는 `inhyk/seonn-publisher` private 레포로 따로 뒀지만, 허브 레포(`inhyuk-world`) 안 `tools/`로 합쳤다.
  도구가 쓰는 `games.json` 스키마와 그걸 읽는 사이트 코드가 서로 다른 레포에 있으면
  한쪽만 고친 반쪽짜리 상태가 그대로 커밋·배포될 수 있기 때문이다 (실제로 `games.json` /
  `games.ts` 불일치 사고가 한 번 났다). 합친 뒤로는 그 불일치가 한 커밋 안에서 드러난다.
  부수 효과로 허브를 clone/pull 하던 로직이 통째로 사라졌다.
  도구는 사이트와 함께 public이 되지만 토큰 같은 비밀은 들어있지 않다.

## 범위

**포함**

- `/publish-game` 스킬 (전역 설치, 심볼릭 링크 방식)
- 허브를 `games.json` 기반으로 전환 (프로그램이 안전하게 고칠 수 있도록)
- 허브가 썸네일/스크린샷을 실제로 렌더링하도록 수정 (이모지 폴백 유지)
- 1회성 백필: `minecraft`, `diep-io`, `bean-dash-arena`, `sans-boss-fight` 등록 + `hotel-tycoon` 전체 발행
- Rhythm Game 죽은 주소 수정

**제외**

- 모노레포 마이그레이션
- `~/inhyuk/` 나머지 미완성 게임 일괄 등록
- 허브 사이트 디자인 리뉴얼

## 성공 기준

- 새 게임 폴더에서 `/publish-game` 한 번으로 seonn.dev에 카드가 뜬다
- 백필 후 사이트 게임 수가 2개에서 7개가 된다
- 같은 게임을 다시 발행하면 중복 추가되지 않고 기존 카드가 갱신된다
- 사이트의 모든 플레이 버튼이 살아있는 주소를 가리킨다

## 설계 메모

**왜 `games.ts`를 `games.json`으로 바꿨나**
: TypeScript 배열 리터럴을 스크립트로 안전하게 고치는 건 깨지기 쉽다. JSON이면 읽고 쓰는 게 확실하다. `games.ts`는 JSON을 읽어 정렬만 하는 얇은 로더로 남겼고, `Game` 인터페이스와 헬퍼 함수는 그대로 유지했다

**왜 심볼릭 링크인가**
: 인혁이는 게임 폴더 안에서 `/publish-game`을 친다. 그 위치에서 스킬이 잡히려면 전역 스킬(`~/.claude/skills/`)이어야 한다. 동시에 코드는 git으로 관리하고 싶다. 링크가 두 조건을 같이 만족시킨다. 링크가 안 되는 환경이면 `install.sh`가 복사로 폴백한다

**왜 Playwright에 `channel: "chrome"`인가**
: 번들 크로미움을 따로 받으면 150MB가 넘는다. 맥에 이미 깔린 크롬을 쓰면 npm 패키지만 받으면 된다

## 남은 과제

- 자동 캡처가 게임 시작 버튼을 못 누르는 경우가 있다 — 수동 `screenshots/` 폴더로 우회
- Node 서버형 게임(`minecraft`, `diep-io`)은 Vercel 정적 배포에서 멀티플레이가 동작하지 않을 수 있다
- `~/inhyuk/`의 나머지 게임들은 인혁이와 상의해서 완성도 높은 것부터 하나씩
